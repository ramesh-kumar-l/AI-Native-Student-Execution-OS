# 33 · Retention Strategy

> Retention comes from being **embedded in the workflow**, not from engagement tricks. This is the difference between a tool the user opens because they need to and one they open because they were notified.

---

## The retention thesis

Three reinforcing loops:

1. **Daily execution loop** — App is the morning planner, the day's tracker, the closing reflection.
2. **Memory compounding loop** — The longer a user is here, the more switching costs.
3. **Capability visibility loop** — Users see themselves getting better; reinforcement is intrinsic.

If any of these three loops breaks, retention collapses.

---

## Retention levers we use

- **Open-first habit.** Morning planning is the daily anchor.
- **Stay-open habit.** Workflow sensing + mentor mean the app is "ambient" during work.
- **Close-day habit.** End-of-day reflection + capability check.
- **Switching-cost from memory.** Every day adds to the memory you'd lose by leaving.
- **Artifact ownership.** Shareable outputs are tied to the user's account, not the app's brand.

## Retention levers we explicitly reject

- Streaks, badges, daily-quest gamification.
- Push notifications outside what the user asked for.
- "Time spent" engagement metrics as a product goal.
- Email re-engagement campaigns (low-trust pattern for our audience).
- Dark patterns around offboarding / export.

---

## How we measure retention

See `34-pmf-tracking.md` for the metric ledger. Headline retention metrics:

- D1 / D7 / D30 / D90 user activation cohorts.
- Daily-active-user rate within cohort.
- "Memory mass" — average memory size per active user over time (proxy for switching cost).
- Returning-after-7-day-absence rate (proxy for habit strength).

---

## Retention failure modes we'd be quick to notice

- D7 < 30% in our wedge audience → workflow loops aren't binding.
- Memory mass plateaus quickly → users aren't building real cognition; "feels like a chatbot."
- High churn at day 30 → memory isn't strong enough switching cost.
- Mentor utilization drops as memory grows → mentor isn't using memory well.

Each failure mode has a documented response in PMF tracking.
