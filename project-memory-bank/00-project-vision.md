# 00 · Project Vision

## One-line

**An AI-native operating system for human capability — that helps students and future professionals execute consistently, ship real projects, and compound capability across a lifetime.**

---

## The problem

The next decade rewards builders who can:

- execute consistently (not just plan)
- collaborate with AI fluently (not just prompt)
- compound capability over time (not just absorb tutorials)

Today's tools are mismatched to that reality:

- **LMS / courseware** optimizes for content consumption; capability does not transfer.
- **Project management** tools assume the work is already understood; they don't help you decide what to do or how.
- **AI chatbots** generate output without memory of the user's trajectory; capability does not compound.
- **IDEs** see code but not the learner; the workflow signal is wasted.

The result: a generation of "tutorial-rich, capability-poor" learners who feel busy but stall before employability.

---

## The thesis

> Capability compounds when execution is **tracked, mentored, and remembered** — and when the tools that already sit in the user's daily workflow are the ones doing the tracking.

This product exists to be that layer.

---

## What we are building

A **trust-first, offline-first, local-first** cognition layer with three form factors:

1. **Desktop Execution OS** (primary) — deep work, roadmap planning, project execution, mentor, artifact generation.
2. **VSCode Capability Intelligence Layer** (secondary) — workflow sensing, architecture awareness, capability extraction *inside* the IDE the user already lives in.
3. **Ambient Mobile Cognition Layer** (future) — reflection, reminders, voice-driven nudges.

All three share one cognition memory and one provider-agnostic AI orchestration layer.

See `10-system-architecture.md` for how these compose.

---

## What we are NOT building

- Not a chatbot wrapper.
- Not a "smart notebook" or note app.
- Not a courseware platform.
- Not a code copilot competitor — we use the IDE as a *signal source*, not a code-generation surface.
- Not a closed cloud SaaS — local-first is non-negotiable.

---

## Three transformations the user should feel

1. **Learning → capability.** What you study becomes what you can build.
2. **Capability → employability.** What you can build becomes visible artifacts (portfolio, narrative, evidence) that earn opportunity.
3. **Employability → compounding growth.** Capability persists, deepens, and travels with you across projects, jobs, and years.

If a feature doesn't move a user along this chain, it doesn't belong in the product.

---

## Long-horizon vision

This project's terminal form is **global cognition infrastructure for human capability building** — a thing many millions of people rely on the way they rely on browsers, calendars, and IDEs today.

That horizon shapes every short-term decision:

- We refuse architectural shortcuts that don't scale to that future.
- We refuse data ownership models that betray user trust.
- We refuse AI dependencies that become single-vendor handcuffs.

See `02-long-term-strategy.md` for the arc.

---

## Success criteria (5-year horizon)

- Tens of thousands of daily-active users for whom this is their primary execution surface.
- Measurable, defensible PMF among AI-native engineering students and early-career builders.
- A cognition memory that users *refuse to lose* — strong enough that switching cost is high and ownership is real.
- A provider-abstraction layer that lets the platform survive any AI vendor turning hostile or going dark.
